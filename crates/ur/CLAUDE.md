# ur (Host CLI)

Runs on the host macOS system. Connects to `ur-server` via tonic gRPC over TCP at `127.0.0.1:12321` (default). Set `server_port` in `ur.toml` to override.

- Server port: read from `config.server_port` (defaults to 12321)
- Auto-starts `ur-server` via Docker Compose if not running — uses `compose_file` from `ur.toml` (default: `~/.ur/docker-compose.yml`)
- `ComposeManager` in `src/compose.rs` wraps `docker compose` CLI for up/down/status. Compose YAML is generated programmatically at `ur start` time (no static template) via `generate_compose()`.
- Container images are built separately via `scripts/build/image.sh`, not by `ur` itself
- **All worker interactions go through the server via gRPC.** The only direct container access from the CLI is server lifecycle (`ur start`/`ur stop`). Direct Docker manipulation from the CLI is not allowed — it desynchronizes the server's in-memory process table.
- The `ur-server` container has **no Docker socket dependency**. Worker launch, stop, network inspect, and squid exec are all delegated to builderd (`BuilderContainerService`) over gRPC. builderd holds Docker socket access on behalf of the server.
- `worker launch` resolves the image from the project's `container.image` config (errors if no project or no image configured), then calls WorkerLaunch RPC; `-f` stops existing worker first via WorkerStop RPC
- `worker stop` / `worker kill` both call WorkerStop RPC
- `ur stop` stops running workers via WorkerStop (warnings only), then local workers directly through builderd (`builderd::stop_local_workers`: `ListLocalWorkers` → `StopLocalWorker` each) before `compose down`, and again after it (catching a launch the server finished during the first sweep) before builderd shutdown; a list or stop failure aborts `ur stop`, and a builderd that is not running only warns. This is the one place the CLI calls builderd's local worker service directly: it must see every live session regardless of row status. The order is `builderd::shutdown_sequence` (sweep → compose down → sweep → stop builderd, each step only after the previous succeeded) and `local_stop_endpoint` (`None` unless a live `builderd` process owns the PID file).
- `start_builderd` waits (≤30s, `spawn_until_listening` → `wait_for_builderd`) for builderd's port; builderd exits when startup adoption fails, so an early exit or timeout is an error naming `builderd.log*` and `builderd.err`
- `worker attach`, `launch -a` and `--rm` go through `AttachManager` (`src/attach.rs`): `resolve` finds the worker in `WorkerList` (newest running row for the id; not `WorkerInfo`, which lacks the full worker id), and `plan_for` branches on `runtime`. Container: `docker exec -it <prefix><id> tmux -u attach-session -t =agent` via the container runtime directly — temporary until a proper attach RPC exists. Local: host `tmux -L ur_config::LOCAL_TMUX_SOCKET -u attach-session -t =ur-<worker_id_full>` with `TMUX` unset (nests like the container case); a missing session is an error naming the worker and pointing at `ur worker list`. `wait_ready` runs the Docker health wait only for containers — the local launch RPC returns after builderd created the session. `attach_with_rm` traps SIGHUP/SIGINT/SIGTERM and then stops via the server's WorkerStop (builderd teardown for local).
- **Local projects** (`local = true`, no `repo`): `reject_unsupported_local_launch` in `main.rs` pre-flights every launch — `--dispatch`, any mode other than `manual`, and a missing `-w` are all refused with an actionable message before the RPC. The server enforces the same rules, but failing here means the user gets the reason instead of a pool error. `project add --local` writes `local = true` and derives the key from the directory basename; `project remove` needs no `--force` for a local project. See `docs/codeflows/config.md#local-projects`.
- **`--agent` flag**: `worker launch`, `worker reseed-credentials`, and `worker save-credentials` all take `--agent <name>` (`Option<String>`, no clap `default_value` — the default is config-derived, not a literal). `resolve_launch_agent_flag` validates launch's flag and returns the resolved name (or `""` when omitted, meaning "let the server resolve it": the mode's `agent` field, then the top-level `agent` default). `resolve_agent_flag` resolves the credential subcommands' flag against `Config.agent` directly (`handle_worker` receives it as `default_agent` and threads it down) — omitting the flag never falls back to a hardcoded `AgentType::Claude`. An unrecognized name is always a descriptive error naming the flag, never a panic. See `docs/codeflows/config.md#agent-default-precedence`.
- **Per-agent credentials** (`src/credential/`): `mod.rs` holds the `AgentCredentialManager` trait, `credential_manager_for()`, `ensure_credentials_for_all_agents()`, and shared helpers; each agent has one manager module. Claude reads its host keychain/file, Codex reads `~/.codex/auth.json`, and AGY reads the `gemini`/`antigravity` OS-keyring entry (macOS Keychain or Linux Secret Service), falling back to its Linux token file. AGY may still bootstrap interactively into the mode-600 `$UR_CONFIG/agy/antigravity-oauth-token` bind mount when no host login exists. Never mount the wider `.gemini` tree, which contains worker-local state.
- **`ur dream`** (`src/dream/`): the mechanical half of the `brain:dream` skill, local only (no server). Resolves the brain via `ProjectConfig::brain_path` (`-p`, then `UR_PROJECT`, then cwd name) and reads the first ```` ```toml ```` block of `<brain>/DREAM.md` (`config.rs`, `deny_unknown_fields`, templates validated against pattern groups). Subcommands: `path`, `config`, `lint`, `refs`, `check [--write]`, `candidates`, `status`, `verify-report`, `try`, `review`, `reviewed`. A stream's frontmatter `ignore_refs` (same `- kind: value` form as `refs`) keeps those refs out of `discovered_refs` and `active_refs`, so `check` never runs them. `check` prints `{summary: {total, done, not_done, unknown, cached}, unknown: [{ref, state, streams}], refs: {<kind:id>: {state, done, checked_at, cached, streams}}}`, where `streams` is `[{stream, source: recorded|discovered}]` over active streams (`check::attribution`, `check::summarize`); `state.json` `refs` stays per-ref `{state, done, checked_at}` with no stream data (rescan to attribute). `candidates` (`candidates::classify`) rescans with `refs::scan`, looks each active stream's recorded+discovered refs up in `state.json` by `Ref::key()` (never re-runs checks), and classifies with `thresholds.quiet_days` (compared to `Stream.quiet_days`, i.e. days since last change): `blocked` if any ref has `done: null` or no cached entry (state `unchecked`), else `possibly_abandoned` if no refs and quiet, else `candidate` if all done and quiet, else `active`. Output `{quiet_days_threshold, summary: {candidate, blocked, possibly_abandoned, active}, streams: {<stream>: {classification, quiet_days, last_change, refs: [{ref, source, state, done, checked_at}], blocked_by: [{ref, state}]}}, inactive: {<stream>: status}}`. `status` (`status::status`) reads the newest `.dream/reports/YYYY-MM-DD.md` (`report::Report::newest`; non-date filenames ignored; no dir/no reports → `report: null`, not an error) and prints `{report: {path, date, applied_section, apply_subject, apply_commit, not_proposed: [item]}, uncommitted: {dream: [path], other: [path]}}`: `applied_section` is a heading titled `Applied`, `apply_commit` the newest HEAD commit whose subject is exactly `brain:dream: apply <date>` (null in a repo with no commits), `not_proposed` the list items/paragraphs under `Not proposed (needs a human)` (`report::items`), `uncommitted` from `git status --porcelain=v1 -z --untracked-files=all` split on `.dream/`. `verify-report [report]` (`verify::verify`, read-only) picks the report with `Report::resolve` (default newest, else a date, `<date>.md`, or a path ending `.dream/reports/<date>.md`, always read from this brain; no reports → error "nothing to verify") and judges each heading one level below `## Proposed edits` (`### E<n> <path>: <change>`, fenced headings ignored) with its first `Target blob:` line; prints `{report, summary: {total, ok, blob_mismatch, off_limits, outside_folders, missing, malformed}, edits: [{id, heading, path, target_blob, current_blob, verdict, detail?}]}`. Verdict order: `malformed` (heading not `E<n> <path>`, no `Target blob:` line, or value neither `new` nor ≥7 hex chars), `outside-folders` (absolute, `..`, under `.git/`/`.dream/`, or under a top-level dir not in `folders`; top-level files are inside), `off-limits` (`Config::is_off_limits`), `missing` (hash recorded, no file), `blob-mismatch` (`git hash-object` doesn't start with the recorded hash, `new` but the file exists, or not a regular file), else `ok`. `report.rs` is the shared report parser (`Report::section` ignores headings inside code fences; heading constants `APPLIED`, `NOT_PROPOSED`, `PROPOSED_EDITS`). Git failures there use `files::git_checked` (errors with stderr) rather than `files::git` (returns `None`). `reviewed <file>... <outcome> [--note] [--at <repo>=<sha>]...` (`review::record_all`, validates every file before recording any; prints `{<file>: ReviewRecord}`) resolves each `--at` via `changes::resolve_at` (`git rev-parse --verify <sha>^{commit}` in the repo's clone) against the config's `[[repos]]` (`{name, path, branch = "origin/master"}`, `name` must match `^[\w-]+$` like frontmatter keys; `Repo::dir` expands `~/`, relative paths are under the brain) — unknown repo, repeated repo, missing clone or bad sha is a command error — and stores the full shas in that review's `ReviewEntry.at` (`#[serde(default)]`, so old `state.json` loads). `review` adds `changes_since: {<picked file>: {<repo>: {since, reviewed_on, branch, sources, commits, paths, error?}}}` (`changes::since`): per repo the newest recorded sha (`ReviewRecord::latest_at`), `git rev-list --count` and `git log --format= --name-only` over `<since>..<branch>` in the clone, limited to the doc's frontmatter `sources` (`- <repo>: <path>` items, `Frontmatter.sources`). Never fetches. A `sources` path absent at both `since` and `branch` (`git cat-file -e`) is a per-repo error, not `commits: 0`. `reviewed` records a repeated file once. A per-repo failure sets `commits`/`paths` to `null` with `error` (never empty lists); the command itself still succeeds. Everything prints JSON; only `check --write` and `reviewed` write, and only `<brain>/.dream/state.json`. Git runs with `current_dir` (the brain, or a `[[repos]]` clone), never `-C`. Workers reach it through hostexec; `ur.lua` pins `UR_PROJECT` to the worker's project and rejects `-p`.
