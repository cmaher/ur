# builderd

Builder daemon for executing commands and managing containers on the host. Receives
already-validated requests from ur-server and acts on the host filesystem and Docker daemon.

- Standalone binary, runs natively on host (not containerized)
- tonic gRPC server; binds to `127.0.0.1` by default, `--bind` flag overrides (on Linux, `ur start` passes the Docker bridge gateway IP)
- Trusts ur-server completely — no command validation
- Started/stopped by `ur start`/`ur stop`, PID tracked at `~/.ur/builderd.pid`
- Resolves `%WORKSPACE%` prefixes in both `command` and `working_dir` via `--workspace` CLI flag or `BUILDERD_WORKSPACE` env var
- Exposes five gRPC services on the same port:
  - `BuilderDaemonService` (`proto/builder.proto`) — exec arbitrary commands on the host; used for worker hostexec (git, gh via the three-hop pipeline)
  - `BuilderContainerService` (`proto/builder_container.proto`) — worker container lifecycle (launch, stop, exec, network inspect); owns the Docker socket on behalf of the server
  - `BuilderPoolService` (`proto/builder_pool.proto`) — pool slot lifecycle (clone, recycle, branch checkout; release is DB-only, no RPC); owns all pool filesystem and git operations on behalf of `RepoPoolManager`
  - `BuilderLocalWorkerService` (`proto/builder_local_worker.proto`) — host-local worker lifecycle (launch, stop, list)
  - `WorkerDaemonService` (`proto/workerd.proto`) — routed by the `ur-worker-id` header to the local worker's in-process daemon (`workerd_router.rs`); missing header → `InvalidArgument`, unknown id → `NotFound`
- `LaunchWorker` does not report success immediately after `docker run`: it waits up to 60 seconds for the worker image's health check. An `unhealthy` result remains pending because synchronous startup hooks can outlast Docker's health-check start period. If the container exits, builderd captures its last 100 log lines, removes it, and returns `FailedPrecondition`.
- `--config-dir` flag (default `~/.ur`) sets the root config directory; used by `LocalOverlayManager` to locate local overlay files at `<config_dir>/projects/<project>/local/`
- Local overlays (`overlay.rs`, `LocalOverlayManager`) are installed into pool slots on acquire and kept under `<slot>/.git/ur-overlay/`. Every short-lived `git`/`gh` exec in an overlaid slot is bracketed (conceal → run → reveal before the exit code frame) so git never sees overlays. Any new builderd path that runs git in a slot on a worker's behalf must go through the same bracket. See `docs/codeflows/project-file-mounting.md#hiding-overlays-from-git`
- Local workers (`local_workspace.rs`, `LocalWorkspaceManager`; `local_settings.rs`, `LocalSettingsManager`) build `<workspace_root>/drive/<worker_id>/`: mount/brain symlinks, the slot's Claude memory symlink, and `.ur/{settings.json, instructions.md, plugin/, skill-hooks/}` via the shared workerd init managers (`SkillLayout::ur_plugin()`), plus git hooks into the slot; `build()` returns the `claude` argv. Data-safety rules: teardown removes only symlinks and the drive (`remove_dir_all` never follows links), never a link target; build never clobbers a real non-empty memory dir and refuses mount dests that would nest through another mount's link. Project instructions are inlined (not `@`-imported) because `--append-system-prompt-file` does not expand imports.
- Local worker lifecycle (`local_worker.rs`): `LocalWorkerManager` + `LocalWorkerRegistry`. Launch order and teardown are in `docs/codeflows/builderd.md#builderlocalworkerservice-and-the-routed-workerdaemonservice`. The registry entry (with its `WorkerDaemonServiceImpl`) is inserted before the agent argv is typed, because the agent's SessionStart hook calls NotifyIdle immediately. Teardown from the exit sink must not abort the watcher task (`TeardownCaller::ExitWatcher`). The tmux socket, workspace root, home, agent_shared dir, exit poll interval and an agent-program override are constructor-injected; `local_worker_tests.rs` runs a stub agent on a unique throwaway socket and temp dirs, never the `ur` socket, `~/.ur` or `~/.claude`. builderd sets `UR_WORKERD_ADDR` itself (`host_workerd_addr` in `main.rs`: its listen address, unspecified → `127.0.0.1`); the request env must carry only `UR_SERVER_ADDR` and `UR_WORKER_SECRET`. Skills resolve `host_skills` (server's host `[skills]`) before `<agent_shared>/potential-skills/`, linked under the drive's `.ur/skill-sources/`.
- Restart adoption and teardown order (ur-j5puq): `adopt_existing` runs before `serve` so `ListLocalWorkers` never under-reports live sessions (the server releases slots of unlisted workers). Teardown is kill → workspace teardown → deregister, stopping at the first failure so the worker stays listed for a retried Stop. Never deregister a worker whose session may be alive. Adoption rebuilds identity/agent/slot from the session env and `#{session_path}`; anything builderd needs to adopt must be in builderd's own session env. All ur instances share the `ur` socket: a session is ours only if its `UR_DRIVE` is set and under this builderd's `drive_root()` (`owns_session`); any other `ur-*` session (another instance's, or a hand-made one with no `UR_DRIVE`) is never adopted, killed or listed. Of our own sessions, only unusable env (`adoptable`) or an unsupported agent makes one unadoptable (killed); a tmux error reading a live session aborts startup instead. `.ur/owner` in each drive (agent, slot, memory target) gates memory-link removal: only a link still pointing at the recorded target is removed, and `teardown_orphan` keeps it when a registered worker uses the slot. Orphan drive failures at startup are logged only (known limit). Stop is a barrier (`barrier.rs`, `WorkerBarrier`, shared rule for the container service): tombstone, then wait for the id's in-flight launch under its lock, then tear down; a tombstoned launch is refused with `FailedPrecondition`; launches run on their own task. Stop Ok means "not running here and never will be". Stop of an unregistered id kills `ur-<id>` (returning the kill error) unless the session is not ours, and tears down a drive it left. Fault-injection tests route only their fixture's socket through a failing wrapper via `tmux::override_program_for_socket` (no PATH/env mutation). See `docs/codeflows/builderd.md#termination-paths-and-reconciliation-ur-j5puq`.
- `--agent-shared` (default `<config_dir>/agent-shared`, filled by `scripts/build/install.sh`) is the local workers' asset root (`potential-skills/`, `instructions/`, `shared-instructions/`).
